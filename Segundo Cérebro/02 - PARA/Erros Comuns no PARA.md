> [!info] Contexto desta nota

> [!summary] Em uma frase
> O PARA falha quando vira **taxonomia** (muitas pastas, muita profundidade) ou quando deixa de **fluir** (nada é arquivado).

## 1. Projeto que é área
**Sintoma:** `1 - Projects/Saúde`, `1 - Projects/Aprender Inglês`.
**Correção:** se não tem fim, é área. Projeto seria "Fazer 30 aulas de inglês até dezembro".

## 2. Pastas profundas demais
**Sintoma:** `3 - Resources/Programação/Backend/PHP/Laravel/Livewire/v3/Componentes/`.
**Correção:** no máximo 2 níveis. O resto é link, tag ou MOC.

## 3. Nunca arquivar
**Sintoma:** 25 "projetos ativos", metade parada.
**Correção:** revisão mensal. Parado há 30 dias e sem plano: arquivar (ou mover para "algum dia" no GTD).

## 4. Recursos virando depósito
**Sintoma:** `3 - Resources/` com 400 notas soltas sem subpasta, link ou uso.
**Correção:** capture menos ([[Os 12 Problemas Favoritos]]) e use [[Zettelkasten Method]] para o que for ideia, não só material.

## 5. Gastar tempo demais decidindo
**Sintoma:** 5 minutos pensando se algo é área ou recurso.
**Correção:** a decisão é reversível. Escolha qualquer uma em 30 s. Você move depois.

## 6. Duplicar notas em várias pastas
**Sintoma:** a mesma nota copiada em projeto e em recurso.
**Correção:** uma nota, um lugar. Do outro lado, um link.

## 7. Usar PARA para ideias
**Sintoma:** você espera que o PARA te ajude a pensar ou ter ideias.
**Correção:** PARA é para **achar e usar**. Para pensar, Zettelkasten. Ver [[Comparativo Completo dos Métodos]].
